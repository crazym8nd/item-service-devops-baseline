# item-service Specification

## Purpose
Минимальный REST-сервис с персистентной сущностью и работающими
health/metrics эндпоинтами, служащий реалистичной основой для
DevOps-скриптов (бэкап реальной БД, health-check реального приложения).

## Requirements

### Requirement: Создание сущности Item
Система SHALL предоставлять эндпоинт `POST /api/items`, принимающий JSON
`{"name": "<string>"}` и сохраняющий сущность `Item` (поля `id` — генерируемый
идентификатор, `name` — обязательная строка) в PostgreSQL.

#### Scenario: Успешное создание с валидным именем
- **WHEN** клиент отправляет `POST /api/items` с телом `{"name": "test"}`
- **THEN** система возвращает статус 201, тело ответа содержит сгенерированный
  `id` и `name = "test"`, запись сохранена в таблице `items`

#### Scenario: Отклонение пустого имени
- **WHEN** клиент отправляет `POST /api/items` с телом `{"name": ""}` или без
  поля `name`
- **THEN** система возвращает статус 400 и не создаёт запись в БД

### Requirement: Схема БД управляется миграциями
Система SHALL создавать и поддерживать схему таблицы `items` через
версионированные Flyway-миграции, а не через автоматическую генерацию схемы
ORM во время выполнения приложения.

#### Scenario: Старт приложения с валидной схемой
- **WHEN** приложение запускается после того, как Flyway-миграции успешно
  применены к целевой БД
- **THEN** Hibernate проверяет соответствие сущности `Item` существующей
  схеме в режиме `validate` и не пытается изменить структуру таблицы

### Requirement: Health-эндпоинт отражает реальное состояние зависимостей
Система SHALL предоставлять `GET /actuator/health`, статус которого зависит
от фактической доступности соединения с PostgreSQL.

#### Scenario: БД доступна
- **WHEN** приложение имеет рабочее соединение с PostgreSQL
- **THEN** `GET /actuator/health` возвращает HTTP 200 с телом, содержащим
  `"status":"UP"`

#### Scenario: БД недоступна
- **WHEN** соединение с PostgreSQL не может быть установлено
- **THEN** `GET /actuator/health` возвращает HTTP 503 с телом, содержащим
  `"status":"DOWN"`

### Requirement: Метрики в формате Prometheus
Система SHALL предоставлять `GET /actuator/prometheus`, отдающий метрики
приложения (JVM, HTTP-запросы) в текстовом формате, совместимом с
Prometheus scrape.

#### Scenario: Скрейп метрик
- **WHEN** внешний коллектор выполняет `GET /actuator/prometheus`
- **THEN** ответ имеет HTTP 200 и `Content-Type` формата Prometheus exposition
  (`text/plain; version=0.0.4` или совместимый)
