## Purpose

Идемпотентный, безопасный по правам доступа скрипт резервного копирования
PostgreSQL, который сам проверяет целостность созданного бэкапа и
автоматически освобождает место, удаляя устаревшие копии.

## ADDED Requirements

### Requirement: Создание сжатого дампа БД
Скрипт `backup.sh` SHALL создавать дамп базы данных через `pg_dump`,
сжимать его (gzip) и сохранять в директории `backups/` с именем файла,
включающим имя базы и временную метку в формате `YYYYmmdd_HHMMSS`.

#### Scenario: Успешное создание бэкапа
- **WHEN** скрипт запускается при доступной БД и достаточном свободном месте
  на диске
- **THEN** в `backups/` создаётся файл `<db>_<timestamp>.sql.gz`, скрипт
  завершается с кодом 0, событие записано в лог с меткой времени

#### Scenario: БД недоступна
- **WHEN** скрипт не может подключиться к БД (неверные креды, БД не
  запущена, сеть недоступна)
- **THEN** скрипт завершается с ненулевым кодом возврата, не создаёт частично
  записанный файл бэкапа, пишет понятное сообщение об ошибке в лог

### Requirement: Проверка целостности созданного бэкапа
Скрипт SHALL проверять целостность каждого созданного архива сразу после
его создания: контроль целостности gzip-архива и сверка SHA256-суммы файла
с сохранённым контрольным значением.

#### Scenario: Бэкап цел
- **WHEN** проверка целостности архива (`gzip -t` или эквивалент) и проверка
  SHA256-суммы проходят успешно
- **THEN** рядом с файлом бэкапа сохраняется файл `<файл>.sha256`, скрипт
  логирует успешную проверку и завершается с кодом 0

#### Scenario: Бэкап повреждён
- **WHEN** проверка целостности архива обнаруживает повреждение (например,
  диск заполнился во время записи)
- **THEN** скрипт помечает бэкап как невалидный в логе, завершается с
  ненулевым кодом возврата и не включает повреждённый файл в ротацию как
  валидный бэкап

### Requirement: Ротация устаревших бэкапов
Скрипт SHALL удалять файлы бэкапов (и соответствующие им `.sha256`-файлы) в
`backups/`, возраст которых превышает 7 дней, после успешного создания
нового бэкапа.

#### Scenario: Есть устаревшие бэкапы
- **WHEN** в `backups/` присутствуют файлы старше 7 дней
- **THEN** скрипт удаляет их вместе с соответствующими `.sha256`-файлами и
  логирует, сколько файлов удалено

#### Scenario: Устаревших бэкапов нет
- **WHEN** в `backups/` нет файлов старше 7 дней (например, первый запуск)
- **THEN** шаг ротации не удаляет ничего и завершается без ошибки
  (идемпотентность)

### Requirement: Безопасное хранение бэкапов и секретов
Скрипт SHALL создавать директорию `backups/` с правами доступа `700` и
файлы бэкапов с правами `600`, и SHALL получать учётные данные БД из
переменных окружения/`.env`-файла, не хардкодя их в коде скрипта.

#### Scenario: Проверка прав после создания бэкапа
- **WHEN** бэкап успешно создан
- **THEN** директория `backups/` имеет права `700`, файл бэкапа и файл
  `.sha256` имеют права `600`

### Requirement: Восстановление из бэкапа
Проект SHALL содержать скрипт `restore.sh`, восстанавливающий базу данных из
ранее созданного бэкапа: перед применением проверяется SHA256-сумма файла,
затем архив распаковывается и применяется через `psql`.

#### Scenario: Успешное восстановление
- **WHEN** пользователь запускает `./restore.sh backups/<db>_<timestamp>.sql.gz`
  при доступной БД
- **THEN** скрипт проверяет SHA256-сумму файла, применяет дамп и завершается
  с кодом 0

#### Scenario: Повреждённый бэкап
- **WHEN** SHA256-сумма файла не совпадает с сохранённой в `<файл>.sha256`
- **THEN** скрипт завершается с ненулевым кодом возврата и не применяет дамп
