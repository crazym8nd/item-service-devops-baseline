## Purpose

Воспроизводимый локальный запуск приложения и базы данных через Docker
Compose с корректным порядком старта: схема БД гарантированно накатана до
того, как приложение начинает принимать трафик.

## ADDED Requirements

### Requirement: Сборка образа приложения
Проект SHALL содержать `Dockerfile`, производящий multi-stage сборку:
стадия сборки использует JDK и Gradle wrapper, стадия runtime использует
минимальный JRE-образ (`eclipse-temurin:24-jre`, версия из
reference-проекта) и запускает процесс от непривилегированного
пользователя.

#### Scenario: Локальная сборка образа
- **WHEN** выполняется `docker build` в директории `item-service/`
- **THEN** сборка завершается успешно и итоговый образ запускает JVM-процесс
  не от `root`

### Requirement: Оркестрация через Docker Compose
Проект SHALL содержать `docker-compose.yml`, описывающий сервисы `db`
(PostgreSQL с healthcheck), `migrate` (одноразовое применение
Flyway-миграций) и `app` (приложение), где `app` стартует только после
успешного завершения `migrate`.

#### Scenario: Полный запуск стека
- **WHEN** выполняется `docker compose up`
- **THEN** сервис `db` становится healthy, сервис `migrate` успешно
  применяет миграции и завершается с кодом 0, после чего запускается
  сервис `app`, и `GET /actuator/health` на `app` возвращает `"status":"UP"`

#### Scenario: Повторный запуск не ломает существующие данные
- **WHEN** стек, уже содержащий данные в `db`, останавливается и запускается
  заново без удаления volume
- **THEN** сервис `migrate` завершается успешно (миграции идемпотентны,
  повторное применение уже применённых версий не производится), ранее
  сохранённые записи в таблице `items` остаются доступны

### Requirement: Конфигурация через переменные окружения
Проект SHALL передавать учётные данные БД и прочие настраиваемые параметры в
сервисы `db`, `migrate` и `app` через переменные окружения, значения которых
берутся из `.env`-файла (не закоммиченного в репозиторий), с шаблоном
`.env.example` в репозитории.

#### Scenario: Запуск без реального .env
- **WHEN** разработчик клонирует репозиторий и копирует `.env.example` в
  `.env` перед первым запуском
- **THEN** `docker compose up` использует значения из `.env` без
  необходимости редактировать `docker-compose.yml`
